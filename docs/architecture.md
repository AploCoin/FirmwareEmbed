# Firmware architecture

`setup()` reads public configuration once, waits for network and certificate time, provisions the restricted RAM-only key and starts the application. `loop()` checks connectivity, runs one work/receipt step and yields. Missing configuration never reaches networking or secret input.

- `ConfigValues.cpp` checks the complete public configuration and parses positive decimal chain/budget values with overflow protection. Failed parsing clears both outputs. `DeviceSetup.cpp` assigns the validated policy, selects network/TLS settings and constructs the single Web3 only after DHCP. The build profile supplies RPC URLs and per-endpoint CA trust; the application synchronizes certificate time before provisioning.
- `SessionProvisioner.cpp` reads a non-echoed serial line. `SessionKeyImport.cpp` imports it, checks the approved signer address and clears the temporary binary secret, including failure paths. The character buffer is wiped after the synchronous callback. A rejected import clears the key.
- `BoardRuntime.cpp` owns serial initialization, association/DHCP recovery, certificate-time synchronization, platform heap diagnostics and cooperative scheduling. Its network setting pointers borrow static configuration strings. ESP8266 retains its disconnect handler, clears stale IP settings, waits at least 45 seconds and yields. ESP32 resets persisted radio state; C3 disables Wi-Fi sleep and retains USB flags.
- `MiningApplication.cpp` owns one SessionKeys adapter, one MiningEmbed facade, one Submission display state and receipt timing. Its one-shot `begin` borrows the setup-owned Web3 and SessionKey; MiningEmbed copies the public session policy. Both borrowed objects outlive the application. It checks outstanding work before starting any batch, reports read/search/submit errors and polls the same hash until confirmation/revert. Firmware does not create an owner signer or resend an uncertain transaction.

AploEmbed owns HTTPS/RPC, exact integers, ABI, signing, registry checks and receipt parsing. MiningEmbed owns parameter decoding, fixed-buffer search, final authorization/challenge revalidation and transaction construction. Firmware tests script those boundaries to verify orchestration; actual protocol correctness is covered by library and isolated-devnet verification.

Each folder under Firmware contains its own application sources, BoardRuntime, build settings and dependency lock. It can be copied independently and built against the two library checkouts. Keep platform workarounds and memory reductions in the affected project's BoardRuntime or application. Shared protocol and mining changes belong in the libraries. Update each project's lock after it has been verified with the new library revisions.

Successful compilation establishes neither TLS heap headroom nor watchdog stability. Linker static RAM excludes runtime TLS buffers, heap, fragmentation and stack peaks. Free heap/largest block diagnostics are present around startup and work batches; hardware evidence must identify the exact flashed image and test conditions.
